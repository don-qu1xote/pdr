# Комментарии

**В коде остаются только комментарии, без которых не соберётся или не проверится
сборка.** Всё остальное — нарушение, и его снимает `scripts/check_comments.py`.

Спор о конкретном комментарии решается ссылкой на эту страницу, а не мнением
того, кто громче.

## Почему так

**Пояснение в коде — признак того, что код непонятен.** Чинить надо код:
переименовать, разбить, вынести значение в константу с именем. Сноска оставляет
непонятный код на месте и добавляет к нему текст, который никто не проверяет.

**Комментарий устаревает молча.** Компилятор не читает его, тесты не падают из-за
него, ревью его пропускает — он же не менялся. Через год он врёт с тем же
уверенным видом, что и в день, когда его написали, и обходится дороже, чем если
бы его не было вовсе: неверному объяснению верят.

**Язык проекта — русский.** Смешивать два языка в одном файле хуже, чем выбрать
один, поэтому английских комментариев нет нигде.

## Что остаётся

| Вид | Пример | Почему |
| --- | --- | --- |
| прагмы и директивы инструментов | `// NOLINT(bugprone-*)`, `# noqa: E501`, `// clang-format off`, `# syntax=docker/dockerfile:1`, `// штатное-ok: ring-buffer — в userver его нет` | без них инструмент ругается или ведёт себя иначе |
| doc-комментарии | `/// Сумма в минорных единицах.`, `"""Что делает функция."""`, JSDoc | это часть публичного контракта, а не пояснение к строчке |
| shebang и кодировка | `#!/usr/bin/env python3` | без него скрипт не запустится |
| закрывающий комментарий пространства имён | `}  // namespace pdr::core` | его ставит сам `clang-format` (`FixNamespaceComments`), снять — уронить `make fmt-check` |
| **русские** комментарии в построечных файлах | Makefile, CMakeLists.txt, Dockerfile, compose, shell, SQL, YAML-конфигурация, `.env` | там комментарий помогает человеку собрать и поднять проект |

Построечные файлы — единственное место, где пояснение оправдано, и даже там
остаётся не всё: английский комментарий, закомментированный код и декоративная
линейка — нарушение и в них.

**Python — это код, а не построечный файл.** Скрипты в `scripts/` — линтеры и
применялка миграций; их «почему» живёт в докстрингах модуля и функций, а не в
строках с решёткой. Докстринги проверка не трогает вовсе.

## Было / стало

### Пояснение к строчке

```cpp
// Было
void Bus::Publish(const Envelope& envelope) {
    // Событие без подписчиков — нормальная жизнь, а не ошибка: издатель и
    // не должен знать, слушает его кто-нибудь или нет.
    const auto found = subscribers_.find(envelope.type);
    if (found == subscribers_.end()) {
        return;
    }
}
```

```cpp
// Стало — то же самое сказано именем и doc-комментарием шины
/// Отправить событие подписчикам. Их может не быть: издатель не знает, слушает
/// ли его кто-нибудь, и это нормальная жизнь, а не ошибка.
void Bus::Publish(const Envelope& envelope) {
    const auto found = subscribers_.find(envelope.type);
    if (found == subscribers_.end()) {
        return;
    }
}
```

### Английский комментарий

```make
# Было
# Runs the formatter over every source file.
fmt:
	@python3 scripts/check_format.py --fix
```

```make
# Стало
# Приводит формат к .clang-format. Ту же цель зовут CI и хук pre-commit.
fmt:
	@python3 scripts/check_format.py --fix
```

### Закомментированный код

```yaml
# Было
  # main:      <<: [*hardening, *logging]   # фаза 1
  #   image: ${MAIN_IMAGE}
  # chat:      <<: [*hardening, *logging]   # фаза 5
```

```yaml
# Стало — состав процессов описан там, где ему место
  # Сервисы появятся по одному, вместе со своей фазой. Имена и состав — в
  # docs/architecture/context-map.md.
```

Закомментированный код не собирается, не проверяется и устаревает молча. Нужен —
верните; не нужен — история хранит его лучше, чем комментарий.

### Декоративная линейка

```python
# Было
# ============================================================
# Разбор
# ============================================================
```

```python
# Стало
```

Разделять код должны пустая строка и имя функции. Рамка из знаков не несёт
сведений и ломается при первой же правке ширины.

### Пояснение, которое оказалось контрактом

```python
# Было
# Список узкий намеренно: похожая формулировка про людей не считается.
MENTIONS = re.compile(...)
```

```python
# Стало — в докстринге модуля, где его прочитают до чтения кода
"""...

Список слов узкий намеренно: похожая формулировка про людей — не про сервис.
"""
```

## Как это проверяется

```sh
make comments        проверить (это же делает CI и хук pre-commit)
make comments-fix    снять нарушения
```

Разбор идёт по языкам: C++ и JS — мимо строковых литералов, Python —
**токенизатором** (решётка внутри строки комментарием не является, и регулярным
выражением это не разобрать), shell, YAML, CMake, Dockerfile и `.env` — по
решётке вне кавычек, SQL — по `--` и `/* */` с учётом долларовых кавычек.

Язык комментария определяется по **блоку** соседних строк, а не по строке: в
русском абзаце попадается строка с одним путём или примером команды, и по
отдельности она выглядела бы английской.

## Чего здесь нет

* **белых списков «этому файлу можно».** Исключение, выданное одному файлу, через
  полгода выдано десяти, а правило превращается в рекомендацию;
* **предупреждений.** Нарушение роняет сборку. Предупреждение, которое ничего не
  роняет, — это строчка в логе, которую пролистывают;
* **проверки того, что `///` действительно документирует объявление.** Переписать
  пояснение в doc-комментарий и тем обойти правило технически можно, и это
  единственное, что остаётся на ревью. Doc-комментарий отвечает на вопрос «что
  это и как этим пользоваться», а не «почему здесь такая строчка».
