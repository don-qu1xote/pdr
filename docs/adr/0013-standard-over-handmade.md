# ADR-0013. Берём штатное: список механизмов, которые не пишутся руками

**Статус:** Принято, 2026-08-22.

## Контекст

В предыдущем проекте руками написаны: свой LRU-кэш, свой ограничитель скорости с
двумя лейнами и токенами, свой размыкатель цепи и свой экспоненциальный откат.
Всё это есть в userver, и было там всё время.

Каждая такая самоделка стоила втрое дороже, чем казалась при написании:

* **свои тесты.** LRU с вытеснением по времени — это десяток граничных случаев,
  и половину из них вспоминают после первого инцидента;
* **своя отладка.** Ограничитель, который «иногда пропускает лишнее», ищут
  сутки, потому что подозревают код вокруг, а не его;
* **свой человек.** Ровно один в команде помнит, почему у размыкателя два порога
  и что будет, если их сравнять. Пока он рядом, самоделка выглядит бесплатной;
* **свой потолок.** Самодельный откат не знает ни про дедлайны запроса, ни про
  отмену задачи, ни про метрики, — и не узнает, потому что дописывать его каждый
  раз дороже, чем кажется.

Соблазн повторить велик и выглядит разумно: «мне нужен маленький кэш на два поля,
не тащить же компонент».

## Решение

**Механизмы из списка ниже не пишутся руками. Берётся штатное.**

| Что нужно | Штатное | Чего не пишем |
| --- | --- | --- |
| кэш в памяти | `cache::LruMap`, `cache::LruSet` | свой LRU, свою вытесняющую мапу |
| кэш справочника с обновлением | `components::CachingComponentBase` | свой класс с `Reload()` и таймером |
| периодическое задание | `utils::PeriodicTask` | поток с `sleep_for` в цикле, `detach()` |
| одиночное задание на кластер | `storages::postgres::DistLock` ([ADR-0011](0011-single-jobs-on-distlock.md)) | блокировку через `update ... set locked` |
| ограничитель скорости | `utils::TokenBucket` | свои токены, свои лейны |
| сброс нагрузки | `congestion_control` | свой размыкатель цепи |
| ограничение повторов | `utils::RetryBudget` | свой экспоненциальный откат |
| таблица соответствий | `utils::TrivialBiMap` | две параллельные `switch` в обе стороны |
| разбор форматов | `formats::parse::To`, `formats::json` | вторую JSON-библиотеку, свой парсер |
| JSON-ручка | `server::handlers::HttpHandlerJsonBase` | свою сериализацию в `HttpHandlerBase` |
| метрики | `utils::statistics` | свой реестр счётчиков, `prometheus-cpp` |
| трассировка | `tracing::Span` | свой идентификатор запроса в логах |
| секреты | `storages::secdist` | чтение своего файла с паролями |
| тестовый контур | `pytest_userver` ([ADR-0012](0012-testsuite-on-pytest-userver.md)) | свой стенд на `subprocess` |

**Проверяется машиной, а не на ревью.** `scripts/check_handmade.py` роняет сборку
на четырёх признаках самоделки:

* класс с именем `*Cache`, `*LruMap`, `*RateLimiter`, `*CircuitBreaker`,
  `*Backoff`, `*TokenBucket`, `*Throttler`;
* мапа с временем жизни, собранная руками: `std::unordered_map` рядом с `ttl`,
  `expires_at`, `evict`;
* периодическое задание на потоке: `std::thread`, `.detach()`,
  `std::this_thread::sleep_for`;
* вторая библиотека вместо штатной: `nlohmann::json`, `rapidjson`,
  `prometheus-cpp`, `opentelemetry`, `spdlog`.

### Если штатного нет

**Своё пишется, только когда штатного нет.** Тогда:

1. в коде ставится директива инструмента с ключом:

   ```cpp
   class RingBuffer final {  // штатное-ok: ring-buffer — в userver его нет
   ```

2. в раздел ниже дописывается строка с ТЕМ ЖЕ ключом, жирным и с причиной:

   ```
   * **<ключ>** — <что это> и почему штатного не хватило.
   ```

Проверка сверяет одно с другим в обе стороны: директива без строки в ADR роняет
сборку, строка без директивы — тоже, иначе список отступлений зарастает мёртвыми
записями. Отступление нельзя сделать молча, и нельзя оставить запись о том, чего
в коде уже нет.

Строка в ADR — не формальность: это место, где через полгода прочитают, почему у
нас своё, и решат, не пора ли его выбросить.

#### Чего в userver нет — отступления

Пока ни одного. Раздел пустой намеренно: это не признак невнимательности, а
факт — все механизмы, которые проекту уже понадобились, в userver есть.

Отступления, которые пришлось сделать раньше и которые здесь НЕ считаются
самоделкой, потому что записаны своими ADR:

* обёртка компонента одиночного задания вместо `DistLockComponentBase` — она
  берёт имя блокировки и её срок из динамического конфига, а не из статического
  ([ADR-0011](0011-single-jobs-on-distlock.md)). Сама блокировка, продление и
  отмена задачи — штатные;
* применялка миграций поверх `psql`: штатной для боевой базы userver не
  предлагает ([ADR-0010](0010-applied-migrations-are-never-edited.md)).

## Последствия

* **«маленький свой кэш на два поля» больше не проходит.** Это и есть цель:
  маленьким он остаётся до первого требования вытеснять по времени;
* **штатное надо изучить.** `CachingComponentBase` с его `Update()`,
  `dump`-ами и `testsuite`-инвалидацией сложнее, чем `std::unordered_map`
  на первой странице. Дальше — наоборот: у него уже есть метрики, дампы,
  прогрев и ручка сброса из теста;
* **проверка ловит по имени, а значит, обходится переименованием.** Это принято:
  линтер закрывает случайную самоделку, а не саботаж. От намеренного обхода
  защищает не grep, а то, что отступление требует строки в ADR;
* **список закрытый и будет расти.** Каждый новый штатный механизм, который мы
  начинаем использовать, дописывается в таблицу вместе с задачей, которая его
  ввела. Механизм, которого в таблице нет, самоделкой не считается — линтер
  проверяет только названное;
* **кэш справочников ещё не заведён.** Ему нужны справочные таблицы, сервис и
  контур; чего именно не хватает — ниже.

### Кэш справочников: что должно появиться раньше

Задача `PDR-ARCH-08` просила завести кэш справочников (предметы, уровни CEFR,
тарифы) на `CachingComponentBase` с инвалидацией из тестов. Сегодня это
невозможно, и вот чего не хватает — по факту, а не по мнению:

| Чего нет | Почему это блокирует |
| --- | --- |
| справочных таблиц в схеме | миграции заводят только `identity_*` и `jobs_*`; ни предметов, ни уровней CEFR, ни `billing_tariff` в схеме нет |
| контекста-владельца | предметы и умения принадлежат `content` (фаза 2): ни модуля `libs/pdr-content`, ни таблиц у него нет. Уровни CEFR не названы даже на карте контекстов |
| сервиса и userver в сборке | `CachingComponentBase` — компонент: он живёт в процессе сервиса, а `services/` не существует и userver в сборке не найден |
| контура pytest_userver | инвалидация из теста — это ручка `tests/control` штатного контура, а он появится вместе с первым сервисом ([ADR-0012](0012-testsuite-on-pytest-userver.md)) |

Когда справочник появится, форма его кэша уже решена и обсуждению не подлежит:
`components::CachingComponentBase` с обновлением из своей таблицы, порт-читатель в
`application` (`application` про userver не знает), инвалидация в тестах — штатной
ручкой контура. Своего кэша не будет и здесь.

## Альтернативы и почему отвергнуты

**Разрешить своё, если «оно маленькое».** Отвергнуто: «маленькое» — это
характеристика первого дня. Свой LRU в предыдущем проекте начинался с
тридцати строк и закончился вытеснением по времени, метриками и своим тестом на
конкурентный доступ.

**Оставить правило в документе без проверки.** Отвергнуто: правило без проверки
через полгода перестаёт соблюдаться. У нас это записано отдельно и проверяется
машиной везде, где возможно, — от границ слоёв до правил колонок.

**Проверять не именами, а анализом кода (clang-tidy, свой матчер AST).**
Отвергнуто по цене входа: матчер AST на «это кэш с TTL» — сам по себе самоделка,
которую придётся содержать. Grep по именам ловит подавляющую часть случайных
самоделок и стоит двести строк с самопроверкой. Если однажды понадобится точнее,
это будет новое решение с новым ADR.

**Запретить всё третьесторонее вообще.** Отвергнуто: смысл не в «только
userver», а в «не писать руками то, что уже есть». `ONNX Runtime`, `llama.cpp`,
`libpq` — сторонние и берутся готовыми ровно по той же логике
([ADR-0001](0001-backend-cpp-userver.md)). Запрещена вторая библиотека там, где
штатная уже есть и используется.
