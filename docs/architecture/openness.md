# Ревизия открытости

Две стороны одного вопроса: **не оказаться запертыми у чужого** и **не запереть
у себя чужое**. Первое — про внешние зависимости, второе — про наши данные.

Правило, из которого всё растёт, — [ADR-0014](../adr/0014-external-apis-are-never-load-bearing.md):
чужой API украшение, несущим он не бывает. Здесь — ревизия по факту кода, а не
по намерению: у каждой строки сказано, что в дереве есть на самом деле.

## Чужое у нас

| Зависимость | Стандарт или проприетарный | Альтернатива | Что при исчезновении | Набор «сервиса нет навсегда» |
| --- | --- | --- | --- | --- |
| Видео (LiveKit) | открытый, лицензия Apache 2.0, самохостится | форк: исходники наши, эксплуатация уже наша | ничего внезапного: сервер стоит у нас, исчезнуть может только проект, а не сервис | `кода нет` |
| Календари | стандарт iCalendar (RFC 5545) | **внешней зависимости нет вовсе**: файл читаем и пишем сами | нечему исчезать | `не требуется` |
| Платёжный провайдер | проприетарный | четыре: ЮKassa, Т-Банк, CloudPayments, Робокасса | приём оплат останавливается, занятия идут; переключение — вторая реализация порта ([ADR-0005](../adr/0005-billing-port-and-first-adapter.md)) | `кода нет` |
| Чеки самозанятого | проприетарно и монопольно | **нет** — см. ниже | репетитор остаётся без чека, а это его обязанность по закону | `кода нет` |
| LLM и эмбеддинги | проприетарный | два российских провайдера плюс своя локальная модель ([ADR-0015](../adr/0015-own-model-for-every-ai-node.md)) | формулировки грубее; факты не теряются — их считает код | `кода нет` |
| Распознавание рукописного | проприетарный | открытые есть, качество низкое | исчезает автоматическая проверка письменной работы; работа сдаётся фотографией репетитору | `кода нет` |

**`кода нет` означает ровно это:** интеграции в дереве нет, реестр
[integrations.md](integrations.md) пуст, инстанцировать набор не для чего.
Пометка не поблажка, а утверждение, которое проверяется:
`scripts/check_openness.py` роняет сборку, если строка помечена `кода нет`, а в
реестре интеграция есть, — и наоборот. Появится интеграция — пометка обязана
смениться на имя инстанцированного набора, иначе сборка красная.

Что именно проверяет набор — [integrations.md](integrations.md), раздел «Набор
„сервиса нет навсегда“». Он написан, проверен на самом себе
(`contract.load_bearing_integration_must_fail`) и ждёт первой интеграции.

### Единственная строка с высоким риском

**Чеки самозанятого.** Остальные пять строк отличаются от неё не степенью, а
видом риска: там альтернатива есть, здесь её нет.

* источник один — ФНС. «Уполномоченные операторы» не альтернатива, а
  посредники к тому же источнику: отказ источника отключает всех сразу;
* зависимость обязательна по закону, а не выбрана нами: чек по каждой оплате
  формирует тот, кто оказал услугу ([ADR-0008](../adr/0008-tutor-is-the-seller.md));
* отказаться нельзя ни ценой функции, ни ценой качества — можно только
  перестать помогать с чеками, то есть выкинуть половину смысла продукта для
  репетитора.

**Митигация — ручной режим:** репетитор выбивает чек сам в «Мой налог», а
продукт хранит состояние «оплата прошла, чек не сформирован», показывает его и
не даёт потеряться. Как состояние домена это уже описано в
[ADR-0008](../adr/0008-tutor-is-the-seller.md).

**Проверить, что ручной режим работает, сегодня не на чем, и это честный ответ
ревизии:** ни таблицы `billing_receipt`, ни адаптера, ни задачи `PDR-BILL-04` в
дереве нет — в `git log` её тоже нет. Строка остаётся с риском «высокий» и
пометкой `кода нет` до тех пор, пока ручной режим не появится вместе с набором,
который его проверяет.

## Наше наружу

Обещание «данные ваши» подтверждается работающей выгрузкой, а не абзацем в
оферте. Ревизия по факту:

| Что | Формат | Работает сегодня | Чем закрывается |
| --- | --- | --- | --- |
| Полная выгрузка аккаунта | JSON, одна команда | **да**: `make account-export TENANT=<uuid> OUT=<файл>` | `db/account/export.sql` |
| История ученика | xAPI | нет | вместе с трекингом прогресса, область `PRG` |
| Задания | QTI | нет | вместе с банком заданий, область `CNT` |
| Материалы | маркдаун | нет | вместе с методическими материалами, область `MEDIA` |
| Расписание | ICS (RFC 5545) | нет | вместе с расписанием, область `SCHED` |
| Контракт API | OpenAPI | нет | область `API` |

Пять строк из шести — «нет», и это не оговорка: **экспортировать сегодня нечего,
кроме того, что уже лежит в схеме.** Ни прогресса, ни заданий, ни материалов, ни
занятий в дереве не существует; обещать их выгрузку и написать «сделано» было бы
ровно тем враньём, ради поимки которого ревизия и делается.

### Полная выгрузка аккаунта

**Одна команда, один файл, всё сразу.** Обещание «данные ваши» не выполняется
набором кнопок «скачать вот эту часть», между которыми человек сам догадывается,
чего он ещё не скачал.

Устроена она так, что расширить её случайно нельзя:

* **границу держит политика, а не запрос.** В `db/account/export.sql` нет ни
  одного условия по арендатору: выгрузка идёт под ролью приложения с
  объявленным арендатором, строки отбирает RLS. Она отдаёт ровно то, что видит
  сам аккаунт, и ни строкой больше;
* **колонки не перечисляются.** `to_jsonb(строка)` берёт их все, поэтому новая
  колонка попадает в выгрузку сама;
* **мусор вместо идентификатора роняет команду,** а не превращается в пустой
  файл, который примут за «данных нет».

Что входит — по одной части на доменную таблицу:

| Часть | Что в ней |
| --- | --- |
| `identity_tenant` | сам арендатор: имя, зона, когда заведён |
| `identity_person` | люди: репетитор, ученики, опекуны, их контакты |
| `identity_role_assignment` | кто кем является в этом аккаунте |
| `identity_guardianship` | связи опекуна с учеником, выдача и отзыв |
| `identity_access_log` | кто и когда смотрел запись занятия, транскрипт или переписку |
| `observability_product_event` | продуктовые события арендатора — обезличенные, но его |

**Таблица, которой нет в выгрузке, роняет сборку.** Проверка сверяет части с
миграциями: каждая таблица с `tenant_id` обязана быть либо в выгрузке, либо в
списке ниже — с причиной. Молчаливо забыть таблицу нельзя.

| Таблица | Почему это не данные аккаунта |
| --- | --- |
| `jobs_effect` | след механизма «это уже сделано», а не факт предметной области; арендатор в нём есть, потому что действие всегда чьё-то |
| `identity_credential` | хеш пароля — секрет входа, а не факт о человеке; выгружать его значит раздавать материал для перебора, а узнать из него человеку нечего |
| `identity_session` | ДЕЙСТВУЮЩИЕ КЛЮЧИ ДОСТУПА. Выгрузка, содержащая живой идентификатор сессии, — это выгрузка, которой можно войти; колонки не перечисляются (`to_jsonb`), поэтому «отдать без идентификатора» здесь не выражается |
| `identity_one_time_token` | то же самое: отпечатки живых одноразовых ссылок |
| `identity_login_attempt` | счётчик механизма: только отпечатки и число попыток, ни почты, ни адреса в нём нет вовсе |

## Что проверяет машина

`python3 scripts/check_openness.py` (и он же в CI) роняет сборку, если:

* у строки таблицы открытости нет пометки о наборе «сервиса нет навсегда», или
  пометка разошлась с реестром интеграций: `кода нет` при живой интеграции и
  имя набора при отсутствующей — одинаково ложь;
* доменная таблица (та, у которой есть `tenant_id`) не попала ни в выгрузку, ни
  в список «не данные аккаунта»;
* выгрузка называет таблицу, которой нет в миграциях;
* в таблице постулатов ([postulates.md](postulates.md)) есть строка без ссылки
  на существующий тест и без явной пометки «намерение».

Чего проверка не делает: она не запускает выгрузку. Это делает
`make account-export` на живой базе — и в CI тоже, вместе с остальными
проверками, которым нужна поднятая установка.
